# 3.17 单项整改记录：SQL 初始化脚本硬编码默认凭据

## 一、原审计项
- 原报告编号：3.17
- 风险等级：高风险
- 原问题：SQL 初始化脚本为 4 个账户设置相同的硬编码默认密码（报告指出为 admin123），攻击者可利用公开/已知默认凭据直接登录。
- 涉及账户：admin、coop01、tech01、farmer01。
- 原报告修复方向：移除源码中的固定默认凭据，部署时使用独立强密码/安全哈希，并要求初始凭据轮换。

## 二、当前代码核验
当前 main 中未直接搜索到明文 `admin123`，但在以下两个初始化脚本发现 4 个账户均使用同一个固定 BCrypt 哈希：
- `Traeppp09/sql/barn_database_rebuild.sql`
- `Traeppp09/sql/barn_schema_only.sql`

账户：
- admin
- coop01
- tech01
- farmer01

四个账户密码字段均为：
`$2a$10$7JB720yubVSZvUI0rEqK/.VqGOZTH.ulu33dHOiBE8ByOhJIrdAu2`

因此即使当前源码没有明文 admin123，固定且重复的已知默认哈希仍保留了原报告描述的默认凭据风险。不能通过“明文已经变成 BCrypt”判定问题消失。

## 三、实际整改
### 1. barn_database_rebuild.sql
删除 4 个默认可登录账户的 INSERT 记录及固定 BCrypt 哈希。

### 2. barn_schema_only.sql
删除同一组 4 个默认可登录账户的 INSERT 记录及固定 BCrypt 哈希。

两个脚本现在只保留表结构，并明确说明：
- 源码不创建带固定默认密码的可登录账户；
- 首次部署使用安全初始化模板；
- 禁止向版本库提交初始明文密码或固定可复用哈希。

### 3. 新增安全初始化模板
新增：
`Traeppp09/sql/sys_admin_secure_seed.template.sql`

模板不包含真实密码或可登录固定哈希，仅提供：
`<REPLACE_WITH_ENV_SPECIFIC_BCRYPT_HASH>`

部署要求：
- 每个环境生成独立强随机初始密码，建议至少 16 位；
- 使用与应用 BCryptPasswordEncoder 兼容的 BCrypt 哈希；
- 真实密码/哈希不得提交 Git；
- 首次登录立即更换初始密码；
- 不再为 admin/coop/tech/farmer 批量设置共享默认密码。

## 四、静态复核
整改后复核三个相关文件：
- 已知固定 BCrypt 哈希：0；
- 明文 admin123：0；
- coop01 默认种子：0；
- tech01 默认种子：0；
- farmer01 默认种子：0；
- 安全模板仅保留不可直接使用的占位符。

## 五、现网与 Git 历史处置要求
源码整改无法自动撤销已经部署到数据库中的旧凭据，也无法抹除 Git 历史提交中的旧哈希。

因此如果这四个账户曾在测试、演示或生产环境实际创建，必须在数据库/账户管理系统中：
1. 立即轮换 admin、coop01、tech01、farmer01 的密码，或禁用不需要的账户；
2. 每个账户使用不同的强随机密码；
3. 检查这些默认凭据是否在其他环境复用；
4. 检查异常登录记录；
5. 如需彻底清除 Git 历史中的敏感凭据，应另行执行仓库历史清理与所有相关凭据轮换。仅删除当前 main 文件内容不等于历史秘密消失。
