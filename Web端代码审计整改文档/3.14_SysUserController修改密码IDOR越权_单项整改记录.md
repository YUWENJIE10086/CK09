# 3.14 单项整改记录：SysUserController 修改密码 IDOR/越权

## 一、原审计项
- 原报告编号：3.14
- 风险等级：高风险
- 原问题：用户自行修改密码接口从请求体读取 `userId`，被操作对象由客户端指定，没有与当前登录身份绑定，存在 IDOR/越权风险。
- 原报告修复方向：用户自助操作的目标账户必须取自服务端已认证身份，不能信任客户端传入的 userId。

## 二、代码核验
整改文件：
`Traeppp09/ruoyi-barn/src/main/java/com/barn/system/controller/SysUserController.java`

整改前 `PUT /system/user/updatePwd` 中存在：
`Long id = Long.valueOf(params.getOrDefault("userId", "0"));`
随后：
`SysUser user = sysUserMapper.selectById(id);`

因此被修改账户由请求体决定，而不是由 Spring Security 当前 Authentication 决定。原报告 3.14 问题真实存在。

## 三、实际整改
修改 `updatePwd`：
1. 增加 `Authentication authentication` 参数；
2. 不再读取请求体中的 `userId`；
3. 验证 Authentication 存在且 principal 必须为 `SysUser`；
4. 从 `authentication.getPrincipal()` 获取当前已认证用户；
5. 仅使用 `principal.getId()` 查询待修改账户；
6. 再次确认数据库用户存在且状态正常；
7. 保留旧密码校验；
8. 保留新密码长度校验和 BCrypt 哈希更新。

整改后的对象绑定关系：
`有效 JWT -> JwtAuthenticationFilter -> Authentication principal(SysUser) -> principal.id -> 当前用户数据库记录 -> 修改自己的密码`

客户端即使继续提交其他用户的 `userId` 字段，该字段也不会被 updatePwd 读取或参与账户选择。

## 四、静态复核
对整改后的 updatePwd 方法单独复核：
- 请求体读取 userId：false；
- Authentication 参数：true；
- 通过 principal.getId() 查询目标账户：true；
- 原密码 BCrypt 校验：true。

因此原攻击链“修改请求体 userId -> 指向其他账户”已经被切断。

## 五、边界说明
`PUT /system/user/resetPwd/{id}` 是代码注释定义的“管理员重置密码”入口，它本来就需要指定目标用户 id。该入口是否只有管理员可调用属于角色权限/RBAC问题，将在原报告 3.16 中统一整改，不应通过删除其目标 id 来替代管理员授权控制。

同理，SysUserController 其他管理接口的批量赋值问题属于 3.15，角色控制问题属于 3.16，本项不提前混改。
