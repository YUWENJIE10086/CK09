# 烤房管理系统 Web端 Vibe Coding 提示词

---

## 一、项目概述

开发一个**烤房全周期信息化管理平台**的Web端，用于烟草行业烤房的信息化管理、预约调度、维修管护、评价反馈和智能决策。系统面向技术员、合作社、站管理员、县区局管理员、市局管理员等多级角色，实现"底数清、状态明、过程管、辅助决策"四大目标。

**技术栈**：
- 前端：Vue3 + Vite + Element Plus + ECharts + Three.js（数字孪生）+ 高德地图API
- 后端：若依（RuoYi-Vue）框架，Spring Boot + MyBatis
- 数据库：MySQL 8.0
- BI看板：集成FineBI
- 小程序端（本次不开发，仅Web端）

---

## 二、角色与权限体系

系统采用五级角色体系，每级角色可查看的数据范围逐级扩大：

| 角色 | 数据范围 | 核心功能 |
|------|----------|----------|
| 烟农 | 所在磅组辖区 | 烤房预约、烤房评价、烤房状态查看（注：烟农主要用小程序，Web端仅做极简适配） |
| 技术员 | 所属烟站辖区 | 维修提报、烤房信息更新、信息变更审批、现场录入 |
| 合作社 | 所属合作社辖区 | 管护任务分配、维修审核、预约审核、评价管理 |
| 站管理员 | 所属烟站辖区 | 烤房信息查询、维修审批、预约审核、数据统计 |
| 县区局管理员 | 所属县区 | 全县区烤房信息查询、维修审批、资金管理、BI看板 |
| 市局管理员 | 全市 | 全市烤房信息查询、新建烤房、资金分配、BI大屏、数字孪生、系统配置 |

## 四、Web端页面清单与详细设计

### 4.1 登录页

**路由**：`/login`

**设计要求**：
- 全屏背景图（烤房/烟田主题，深色调），中央白色毛玻璃登录卡片
- 顶部Logo + 系统名称"烤房全周期信息化管理平台"
- 账号/密码输入框 + 验证码 + 登录按钮
- 底部版权信息
- 支持记住密码

---

### 4.2 首页/工作台

**路由**：`/dashboard`

**设计要求**：采用卡片式布局，根据角色动态展示不同内容

**通用区域**：
- 顶部：欢迎语 + 当前日期 + 未读消息提醒
- 左侧快捷入口卡片（根据角色不同显示不同入口）

**市局管理员/县区局管理员看板**：
- 烤房总数/正常数/需维修数/退出数（4个数字卡片，带同比环比）
- 健康评分分布饼图（优良/需维护/急需修复/退出）
- 维修资金使用情况柱状图（按县区/按年度）
- 预约使用热力图（按时间段）
- 逾期未归还烤房预警列表
- 最近7天预约趋势折线图

**站管理员/合作社看板**：
- 辖区烤房状态概览（数字卡片）
- 待审核预约列表
- 待审核维修申请列表
- 辖区烤房地图分布（标注状态颜色）

**技术员看板**：
- 我的待办任务（维修提报/信息更新）
- 辖区烤房状态统计
- 最近录入记录

---

### 4.3 烤房信息管理

#### 4.3.1 烤房列表页

**路由**：`/barn/list`

**功能**：
- 顶部筛选区：县区/乡镇/村/烟站/状态/健康等级/部位状态/设备编号/部件名称（联合查询）
- 列表展示：烤房编号、名称、地址、状态标签（颜色区分）、健康评分（进度条）、当前使用人、操作按钮
- 支持导出Excel
- 支持地图视图切换（列表/地图双视图）
- 地图视图：高德地图标注烤房位置，不同状态不同颜色图标，点击弹出信息窗口

**数据范围**：根据角色自动过滤辖区

#### 4.3.2 烤房详情页

**路由**：`/barn/detail/:id`

**功能**：
- 基本信息卡片：编号、名称、地址、建设信息、容量、受益面积
- 五大部位状态卡片（JR/SR/ZK/ZT/FS），每个部位展开显示部件详情（状态、评分、照片）
- 健康评分仪表盘（0-100分，颜色渐变）
- 历史维修记录时间轴
- 预约使用记录列表
- 评价记录列表
- 位置地图（单点标注+导航）
- 预测信息：剩余有效寿命、最优维修时间点

#### 4.3.3 新建烤房

**路由**：`/barn/add`

**权限**：仅市局管理员

**功能**：
- 分步表单：基本信息 → 位置信息 → 部件信息 → 确认提交
- 位置选择：地图选点 + GPS坐标自动回填
- 部件信息：按5大部位14个部件逐项录入初始状态

#### 4.3.4 烤房信息更新

**路由**：`/barn/edit/:id`

**权限**：技术员及以上

**功能**：
- 现场录入模式：支持移动端适配
- 状态判定：逐项核查14个部件，选择状态+上传照片
- 定位赋号：自动获取当前GPS（需授权）
- 变更走审批流

---

### 4.4 维修管理

#### 4.4.1 维修申请列表

**路由**：`/repair/list`

**功能**：
- 筛选：状态/县区/烤房编号/维修类型/紧迫性/申请时间
- 列表：申请编号、烤房名称、维修类型、紧迫性标签（颜色区分）、预估费用、状态流程条、操作
- 状态流程条可视化：申请→审核→公示→审批→实施→验收→审计→兑现→归档（15个环节简化展示）

#### 4.4.2 维修申请提报

**路由**：`/repair/apply`

**权限**：技术员

**功能**：
- 选择烤房（支持搜索/扫码）
- 维修类型选择
- 紧迫性选择
- 损坏描述（富文本）
- 损坏照片上传（支持多张，带水印时间戳）
- 预估费用填写
- 关联部件选择

#### 4.4.3 维修审批

**路由**：`/repair/approve/:id`

**权限**：站管理员/县区局管理员/市局管理员（按级别审批）

**功能**：
- 查看申请详情
- 审批意见填写
- 通过/驳回操作
- 审批记录时间轴

#### 4.4.4 维修验收（线上督办验收）

**路由**：`/repair/accept/:id`

**功能**：
- 实施过程照片查看
- 验收结果填写（合格/不合格）
- 验收照片上传（拍照留痕）
- 验收意见
- 验收后自动触发结算审计流程

#### 4.4.5 维修资金分配

**路由**：`/repair/fund`

**权限**：县区局管理员/市局管理员

**功能**：
- 资金总览：按来源分类的金额统计
- 分配方案：基于算法推荐的最优修复资金分配方案
- ROI动态评估：历史维修投入产出比分析图表
- 紧迫性排序：紧急建议优先分配

### 4.8 BI大屏分析

**路由**：`/bi/dashboard`

**权限**：县区局管理员/市局管理员

**设计要求**：深色主题大屏，1920x1080适配

**模块**：
1. **烤房总览**：总数/各状态数量/健康评分均值（大数字+趋势箭头）
2. **区域分布地图**：全市烤房分布，按县区着色
3. **健康评分分布**：环形图
4. **维修资金分析**：按县区/年度/类型的堆叠柱状图
5. **预约使用分析**：月度预约量折线图、烤房利用率排行
6. **部件状态统计**：5大部位14个部件的状态分布雷达图
7. **预警信息**：滚动播报急需修复烤房、超时未归还、资金不足预警
8. **评价分析**：评分趋势、好评率

**集成方式**：嵌入FineBI iframe 或 自研ECharts大屏

### 4.9 烤房健康评分与预测

**路由**：`/health/analysis`

**权限**：县区局管理员/市局管理员

**功能**：
- 健康评分卡片列表：按评分排序，颜色编码
- 单烤房健康评分详情：各部件评分雷达图、权重分布

## 五、核心算法/模型（后端实现，Web端展示）

### 5.1 烤房自动健康评分算法

```
健康评分 = Σ(部件i评分 × 部件i权重)
```

- 部件评分：基于状态（正常100/损坏按程度30-70/缺失0）+ 图片AI识别修正
- 部件权重：JR=0.25, SR=0.20, ZK=0.20, ZT=0.20, FS=0.15（可配置）
- 健康等级映射：90-100优良 / 70-89需维护 / 40-69急需修复 / 0-39退出

### 5.2 烤房健康状态预测模型

- 基于历史维修记录和状态标签，训练退化曲线模型
- 输出：剩余有效寿命（年）、最优维修时间点
- Web端展示：退化曲线图 + 预警时间线

### 5.3 烤房智能推荐算法

```
推荐得分 = w1×距离分 + w2×空闲分 + w3×偏好分 + w4×评分分
```

- 距离分：基于GPS计算距离，越近分越高
- 空闲分：当前是否空闲 + 未来7天空闲时段匹配度
- 偏好分：烟农历史使用频率
- 评分分：烤房评价均分

### 5.4 维修资金产出分配算法

- 输入：修复紧迫性标签 + 维修预算约束
- 输出：最优修复资金分配方案
- ROI计算：维修后使用年限/轮次 vs 维修费用
