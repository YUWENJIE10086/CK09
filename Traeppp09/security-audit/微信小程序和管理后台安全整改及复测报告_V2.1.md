## 3. 关键代码证据

### 3.1 SQL 动态列名

当前 HealthAlgoController 定义固定算法集合：

- 健康算法：bmhi/fche/topsis/cdci/crhe
- 寿命算法：edrl/wrrl/bdrl/gple

随后使用 requireHealthAlgo 取得规范化算法名，再生成 health_<algo> / life_<algo> 列名。列表和统计查询均基于这一受控值拼接 SQL。

因此，本轮可以确认“列名来源已从任意请求值收缩到固定集合”。

### 3.2 CORS

当前 SecurityConfig：

- 来源来自 CORS_ALLOWED_ORIGINS 对应的 Spring 配置；
- 方法限制为 GET/POST/PUT/DELETE/PATCH/OPTIONS；
- 请求头限制为 Authorization、Content-Type、X-AI-API-Key；
- allowCredentials=false；
- WebMvcConfig 只负责静态资源映射，不再重复注册宽松 CORS。

生产部署不能沿用开发默认来源，必须通过环境变量明确配置可信前端来源。

### 3.3 AI Query

当前 /barn/ai-query/** Controller 具有：

@PreAuthorize("hasAnyRole('ADMIN', 'AI_QUERY')")

同时 ApiKeyAuthenticationFilter 只在目标路径、尚无认证主体且配置了 API Key 时处理 X-AI-API-Key。

API Key 使用常量时间比较 MessageDigest.isEqual，配置来源为 AI_QUERY_API_KEY。

这意味着仓库中没有要求提交真实 API Key；但生产环境若需要 Dify/API Key 调用，必须正确注入该配置。

### 3.4 图片路径

ImageController.resolveOriginalFile() 当前依次执行：

1. 拒绝空路径；
2. 拒绝 http/https 外部 URL；
3. 去除前导斜杠和 upload/ 前缀；
4. 限制 jpg/jpeg/png/gif/webp；
5. 对上传根目录和候选路径执行绝对路径规范化；
6. 要求 candidate.startsWith(basePath)。

该逻辑能够阻断常规 ../ 路径穿越，但生产复测仍建议增加符号链接、大小写后缀、编码绕过及 Windows/Linux 两种路径格式测试。

### 3.5 用户权限

当前 SysUserController 的管理接口明确要求 ADMIN。

updatePwd 不再信任请求体中的用户 ID，而是从 Spring Security 当前认证主体取得 ID，再读取数据库用户。

SysUserDTO 仅包含允许客户端编辑的业务字段；新增用户时服务端强制：

userType = "01"

因此客户端不能通过普通新增请求把自己注册成 00 管理员。

### 3.6 登录保护

当前 LoginController 在查询用户前检查 LoginAttemptService.isLocked()；密码错误进入 recordFailure()。

当前锁定策略为：

- 最大失败次数：5 次；
- 锁定时间：15 分钟；
- 成功登录清除失败状态。

该机制目前是应用内存状态，因此多实例部署时并非分布式限流。这不影响本次对 3.17 的静态整改判断，但正式生产环境建议结合 Redis/网关限流，避免绕过单实例内存计数。

## 6. 本轮发现的残余风险

### R1：仅有静态复测，没有真实环境复测

当前最重要的缺口不是继续改代码，而是证明整改后的程序在真实环境中确实按预期运行。

必须执行：

- Maven test/package；
- 数据库初始化；
- 管理员登录；
- 普通用户登录；
- 普通用户访问管理 API；
- 修改自己的密码；
- 尝试修改他人密码/状态；
- AI Query JWT/API Key 双路径测试；
- 浏览器 CORS 测试；
- 图片路径穿越测试；
- 上传文件真实内容校验；
- Fortify/CODE SEC/人工渗透复测。

### R2：登录锁定是单实例内存状态

LoginAttemptService 使用 JVM 内存 ConcurrentHashMap。

如果生产环境采用多实例部署，攻击者可能通过不同实例分散失败请求。正式生产建议将失败计数迁移到共享存储或在网关层增加限流。

### R3：图片接口公开属性仍需业务确认

当前整改保留 /upload/** 公开访问能力，这是为了不破坏现有图片展示链路。

因此本轮解决的是“不能通过路径穿越读取任意文件”，而不是“所有图片都需要认证”。如果图片属于敏感业务数据，应另行进行访问控制设计。

### R4：旧审计文件/旧归档的扫描边界

仓库仍包含原始：

微信小程序和管理后台代码审计报告 V1.0.docx

如果第三方工具扫描 Git 仓库附件，应避免把历史报告中的旧代码/敏感信息误判为当前交付代码。

正式送审交付物应明确扫描范围，并优先扫描整改后的源码和重新构建的部署包。

- **SQL 标准输出收敛**：移除 MyBatis `StdOutImpl`，避免 SQL 调试输出直接写入标准输出日志，降低 SQL/业务数据进入容器或主机日志的风险。

上述改动已进入 `main`。部署前必须检查环境变量，否则应用会主动拒绝使用弱 JWT 配置启动。
